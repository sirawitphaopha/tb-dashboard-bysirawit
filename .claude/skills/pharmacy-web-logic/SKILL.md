## 1. จับกลุ่มสถิติด้วย "รหัสยา" ไม่ใช่ "ชื่อยา"

### ปัญหา

ชื่อยาที่บันทึกลงเคสเป็น **snapshot ณ วันบันทึก** (ตั้งใจให้เป็นแบบนั้น — ดูข้อ 9)
พอมีคนแก้ชื่อยาในคลัง ยาตัวเดียวกันจะถูกนับเป็นสองตัว

```
Morphine sulfate (MST) 10 mg   คืน 5 ครั้ง   ← ชื่อเก่า
Morphine sulfate 10 mg ER      คืน 3 ครั้ง   ← ชื่อใหม่ ยาตัวเดียวกัน
```

ตัวเลข KPI ที่รายงานผู้บริหารไปแล้วจะเปลี่ยนย้อนหลังโดยไม่มีใครรู้

### โค้ดที่ถูก

```js
// กุญแจจับกลุ่ม — มีรหัสใช้รหัส ไม่มีรหัสใช้ชื่อ
const key = drugId != null ? 'id:' + drugId : 'txt:' + drugName;
// ป้ายที่โชว์ — ใช้ชื่อล่าสุดจากคลังเสมอ
const label = master ? drugFlatLine(master) : drugName;
```

ฝั่ง SQL
```sql
case when r.drug_id is null then 'txt:' || r.drug_name
     else 'id:' || r.drug_id::text end as gkey
...
group by gkey
```

### อยู่ที่ไหน

| เว็บ | ไฟล์ |
|---|---|
| ยาคืน | `scripts/008_group_by_drug_id.sql` → ฟังก์ชัน `mr_summary` · `mr_top_returned` |
| ME-DRP | `components/views/dashData.ts` บรรทัด ~170 |

### วิธีตรวจ

```bash

grep -n '"id:" + id' components/views/dashData.ts
```
```sql

```

### ข้อ 16 — ลูกศรวนรอบ

```js
export function moveHi(current, delta, total) {
  if (!total) return -1;
  if (current < 0) return delta > 0 ? 0 : total - 1;  // ยังไม่ชี้ · กดขึ้น = ไปตัวสุดท้าย
  let next = current + delta;
  if (next < 0) next = total - 1;
  if (next >= total) next = 0;
  return next;
}
```

```js
    return (c === 'x' ? r : (r & 0x3) | 0x8).toString(16);
  });
}
```

**`crypto.randomUUID` มีเฉพาะ https กับ localhost**
เปิดเว็บผ่าน `http://192.168.x.x` (เทสจากมือถือในวงแลนโรงพยาบาล) จะเป็น `undefined`
→ ฐานข้อมูลตีกลับเพราะ id ไม่ใช่ uuid → **ถ้าดัก error เงียบจะขึ้น "บันทึกแล้ว" หลอก ทั้งที่ข้อมูลไม่เข้า**

ME-DRP เคยเจอบั๊กนี้จริง (v0.9.7.3) — รายงานหายไปหลายเคส

### ตัวจับเวลาตัด

```js
export async function fetchT(url, opts, ms) {
  const ac = new AbortController();
```

**บทเรียนจากการย้าย ME-DRP ที่เว็บอื่นยังไม่มี**
1. **เขียนไฟล์ตัวคุยข้อมูลใหม่โดยคงชื่อฟังก์ชันเดิมทุกตัว** → หน้าจอทั้งเว็บไม่ต้องแก้เลย งานกระจุกที่ไฟล์เดียว
2. **`import "server-only"` ในไฟล์ที่ถือกุญแจ** เผลอ import จากฝั่งเบราว์เซอร์เมื่อไหร่ พังตั้งแต่ build ไม่ใช่ไปรู้ตอนกุญแจหลุดขึ้นเว็บจริง (เว็บพี่น้องยังไม่มีตัวนี้)
3. **ปิด RLS เป็นขั้นสุดท้ายเสมอ** ปิดก่อนย้ายเสร็จ = เว็บใช้ไม่ได้ทั้งห้องยาทันที
4. 🚨 **เงื่อนไขที่เคยฝากไว้กับกฎของฐาน ต้องย้ายมาเขียนเองฝั่งเซิร์ฟเวอร์** กุญแจ service role ผ่านทุกกฎ ตาข่ายนั้นหายไปเงียบ ๆ (ME-DRP เคยมีกฎ "ลบได้เฉพาะแถวในถังขยะ")
5. **พิสูจน์ด้วยการยิงจริงด้วยกุญแจเก่า** ทั้งอ่าน เขียน แก้ ลบ แล้วตรวจฐานซ้ำว่าข้อมูลไม่ขยับ — ไม่ใช่แค่ดูว่า policy หายไปจากตาราง

**ประตูรหัสผ่าน — ME-DRP ทำแล้ว 2 ก.ย. 2569 (v0.9.23.0)** ยกกลไกจาก HCV มาทั้งชุด
`middleware.ts` (ด่านที่ 1 กั้นทุกหน้า/ทุก API) + `lib/requireAuth.ts` (ด่านที่ 2 route เรียกเอง)

🚨 **ต้องมีปุ่มออกจากระบบที่ล้างข้อมูลในเครื่องด้วย** ล็อกประตูอย่างเดียวไม่พอ

### 🚨 บัตรผ่านต้องนับอายุจาก "ครั้งสุดท้ายที่ใช้" ไม่ใช่ "วันที่ออกบัตร"

คอมห้องยาเปิดเว็บทุกวัน แต่ถ้านับจากวันที่ออกบัตร **จู่ ๆ วันหนึ่งก็ถูกเด้งออกกลางงาน**
เภสัชกรที่กำลังกรอกยาคืนค้างอยู่ต้องหยุดไปตามหารหัส ซึ่งไม่มีใครจำได้

```js
// lib/auth.js — ใกล้หมดอายุแล้วหรือยัง
export function authCookieStale(value) {
  const at = Number(String(value || '').split('.')[0]);
  if (!Number.isFinite(at)) return false;
  return Date.now() - at > (AUTH_DAYS * 24 * 60 * 60 * 1000) / 2;
}
```
```js
// middleware — ต่ออายุให้เองตอนบัตรผ่านด่าน
const res = pass();
if (authCookieStale(got.value)) {
  res.cookies.set(AUTH_COOKIE, await issueAuthCookie(), authCookieOpts());
}
return res;
```

🚨 **ต่อเมื่อใช้ไปเกินครึ่งอายุแล้วเท่านั้น ไม่ใช่ต่อทุกคำขอ**
ต่อทุกคำขอ = เขียนคุกกี้ใหม่หลายสิบครั้งต่อนาทีโดยไม่ได้อะไรเพิ่ม และตามรอยยากเพราะเวลาขยับตลอด

🚨 **ตัวเลือกของคุกกี้ต้องอยู่ที่เดียว** (`authCookieOpts()`) เพราะมีสองที่ที่เขียนคุกกี้ —
ตอนล็อกอิน กับ ตอนต่ออายุ · เขียนแยกแล้วแก้ที่หนึ่งลืมอีกที่
= บัตรที่ออกกับที่ต่ออายุมีคุณสมบัติไม่เหมือนกัน ซึ่งไม่มีอะไรจับได้เลย

🚨 **ต้องทดสอบด้วยบัตรที่ "แก่" จริง ๆ** สร้างบัตรย้อนเวลาแล้วดูว่าระบบตัดสินยังไง
ไม่ใช่อ่านโค้ดแล้วเชื่อว่าถูก (ยาคืนทำไว้ที่ `scripts/auth-renew-check.mjs` 8 ข้อ)

## 25. เรียงผลค้นหา — จัดกลุ่มตามรูปแบบยาก่อน แล้วค่อยเรียงความแรง

**พี่กันเคาะ 13 ส.ค. 2569** หลังเห็นว่า Morphine 5 รายการเรียงสลับกันไปมาจนหาไม่เจอ

### ปัญหา

ยาชื่อเดียวกันที่มีหลายรูปแบบ เรียงตามความแรงล้วนจะกระจัดกระจาย

```
Morphine sulfate 10 mg/5mL  syrup      ← ยาน้ำ
Morphine sulfate 10 mg      tab (ER)   ← เม็ด
Morphine sulfate 10 mg/mL   injection  ← ยาฉีด
Morphine sulfate 20 mg      cap (ER)   ← แคปซูล
Morphine sulfate 30 mg      tab (ER)   ← เม็ด
```

เม็ดสองตัวอยู่คนละปลาย ทั้งที่เป็นของที่หยิบมาด้วยกันบ่อยที่สุด

**เหตุผลที่ต้องเป็นรูปแบบยา ไม่ใช่ความแรง** — เวลารับยาคืน สิ่งแรกที่เภสัชกรเห็นคือ
**รูปของยาในมือ** (เม็ด ขวด หลอด) ไม่ใช่ตัวเลขความแรง

### โค้ดที่ถูก — `lib/drugSearch.js`

```js
// เรียงจากที่เจอบ่อยสุดในห้องยาไปหาที่เจอน้อย — ยากินก่อน ยาฉีด ยาใช้ภายนอก
const FORM_ORDER = [
  'tab', 'cap',                                                            // ยากินชนิดแข็ง
  'syrup', 'suspension', 'solution', 'elixir', 'oil', 'sachet', 'powder',  // ยากินชนิดน้ำ/ผง
  'injection', 'vial', 'amp', 'prefilled syringe', 'prefilled pen',        // ยาฉีด
  'nebule', 'MDI', 'inhaler', 'turbuhaler', 'spray',                       // ยาพ่น
  'eye drops', 'drops',                                                    // ยาหยอด
  'cream', 'ointment', 'gel', 'paste', 'lotion', 'emulsion',               // ใช้ภายนอก
  'patch', 'suppository', 'implant'
];
const FORM_RANK = new Map(FORM_ORDER.map((f, i) => [f, i]));
function formOf(d) {
  const r = FORM_RANK.get(String(d.form || '').trim());
  return r === undefined ? FORM_ORDER.length : r;   // ที่ไม่รู้จักไปท้ายสุด
}
```

**ลำดับการจัดอันดับฉบับสมบูรณ์ (ห้ามสลับ)**

```
1) เจอที่ต้นชื่อ
2) ตำแหน่งที่เจอ      ชื่อสามัญ 0+ · ตัวย่อ 500+ · ชื่อการค้า 900+
3) ยาที่ใช้บ่อย
4) ชื่อยาตามตัวอักษร   ← กันความแรงเรียงข้ามยา
5) รูปแบบยา           ← ข้อ 25 · จัดกลุ่มเม็ด/น้ำ/ฉีด
6) ความแรงน้อย→มาก
7) ชื่อเต็ม
```

ค้น `morphine` แล้วต้องได้ **เม็ด → เม็ด → แคปซูล → ยาน้ำ → ยาฉีด**

  ประโยชน์: เห็นทันทีว่ายาตัวนี้จะโผล่หน้าตาแบบไหนตอนเภสัชกรค้น โดยไม่ต้องไปเปิดหน้าค้นหา

## 🔴🔴 ห้ามเดาข้อมูลยาแล้วเขียนลงตารางนี้

> **บทเรียนหนัก 12 ส.ค. 2569 — พี่กันโกรธมาก**

แคลร์ใส่ตัวย่อยา **127 ตัว** ลงช่อง `abbrev` เอง โดยพี่กันยังไม่ได้ตรวจ
ในนั้นมีที่ **คิดขึ้นเองล้วน ๆ** — `METRO` · `AMLO` · `SIM` · `OME` · `WAR` · `DICLO`
ซึ่งไม่ใช่ตัวย่อที่เภสัชกรใช้จริง แค่ตัดคำให้สั้น
และใส่ `PARA` ทั้งที่พี่กันสั่งชัดว่าไม่ต้องใส่

**ตารางนี้ใช้ร่วม 3 เว็บ ข้อมูลมั่วกระจายทุกที่ทันทีที่รันคำสั่ง**

### กฎ

- 🚨 **ข้อมูลยาที่ไม่มีแหล่งอ้างอิง = ห้ามใส่** ให้ถามพี่กัน (เภสัชกร) เสมอ
- 🚨 **"ลิสต์มาให้ดู" = ให้เสนอ ไม่ใช่ให้ลงมือ** ต้องรอเคาะก่อน
- 🚨 **แก้ข้อมูลจริงต้องขออนุมัติเป็นรายการ** แสดงตาราง "จากอะไร → เป็นอะไร" แล้วรอ "โอเค"
- 🚨 ข้อมูลผิดในระบบยา = **เลือกยาผิดตัว** ไม่ใช่แค่หน้าจอไม่สวย

**ตัวอย่างที่ผิดพลาดจริง** — `FeSO4` ถูกใส่ให้ `Ferrous fumarate`
แต่ FeSO4 คือ ferrous **sulfate** เป็นคนละเกลือกัน

## 30. ชุดรับมือเน็ตหลุด — ต้องครบทั้ง 5 อย่าง 🔴

**พี่กันสั่ง 31 ส.ค. 2569** หลังถามว่า "ถ้าเน็ตหลุด จะเกิดอะไรขึ้น เราวางแผนเรื่องนี้ยัง"
แล้วต่อด้วย "มันจะขึ้นเตือนไหม แบบเป็นแบนเนอร์ไว้เลย ว่าเน็ตหลุด เหมือนเว็บยาคืน"

เน็ตโรงพยาบาลไม่ได้หลุดแบบขาดสะบั้นอย่างเดียว แบบที่อันตรายกว่าคือ
**"ต่ออยู่แต่ไม่ไปไหน"** — `fetch` จะไม่ throw และไม่ resolve ปุ่มหมุนค้างตลอดกาล

### ต้องมีครบทั้ง 5 อย่าง ขาดข้อใดข้อหนึ่งก็ยังเสียของ

| # | อย่าง | ทำไมต้องมี |
|---|---|---|
| 1 | **แถบเตือนค้างบนสุด** | บอกตลอดเวลาที่เน็ตหลุด ไม่ใช่รอให้กดแล้วค่อยรู้ |
| 2 | **ตัวจับเวลาตัดทุกคำขอ** | เน็ตค้างแบบไม่ตอบ ต้องตัดเองแล้วบอกผู้ใช้ |
| 3 | **ร่างเก็บในเครื่อง** | เผลอปิดแท็บระหว่างเน็ตหลุด ของที่กรอกต้องไม่หาย |
| 4 | **กันบันทึกซ้ำที่ฐาน** (ข้อ 20) | กดส่งใหม่ได้โดยไม่กลัวได้ข้อมูลสองชุด |
| 5 | **เตือนก่อนปิดแท็บ** | มีของค้างยังไม่บันทึก ต้องถามก่อน |

### แถบเตือน — เขียนยังไง

```
เน็ตหลุด — ยังกรอกต่อได้ตามปกติ สิ่งที่กรอกไว้ถูกเก็บในเครื่องนี้แล้ว
                                                    กดบันทึกได้เมื่อเน็ตกลับมา
```

🚨 **ต้องบอกว่า "ของไม่หาย" ก่อน แล้วค่อยบอกว่าให้ทำอะไรต่อ**
ถ้าบอกแค่ "เน็ตหลุด" เภสัชกรจะรีบจดใส่กระดาษเผื่อไว้ ซึ่งเสียเวลาโดยไม่จำเป็น

- สีแดงอิฐ `#c2543c` ตัดกับธีมเว็บชัด เห็นทันทีแม้กวาดตาผ่าน
- **วางเหนือพื้นที่เลื่อน** จะได้ค้างบนสุดเสมอ ไม่เลื่อนหนีไปกับเนื้อหา
- `role="status" aria-live="polite"` ให้โปรแกรมอ่านหน้าจออ่านให้เมื่อสถานะเปลี่ยน
- 🚨 **เช็คสถานะตอนเปิดเว็บด้วย** (`navigator.onLine === false`) ไม่ใช่ฟังแต่เหตุการณ์
  เผลอเปิดตอนเน็ตหลุดอยู่แล้วต้องเห็นป้ายทันที

### ตัวจับเวลาตัด

```ts
export const NET_TIMEOUT = 20000;
export async function fetchT(url, opts = {}, ms = NET_TIMEOUT) {
  if (navigator.onLine === false) throw new Error(NET_OFFLINE_MSG);
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), ms);
  try { return await fetch(url, { ...opts, signal: ac.signal }); }
  catch (e) {
    if (e instanceof DOMException && e.name === 'AbortError') throw new Error(NET_TIMEOUT_MSG);
    throw e;
  } finally { clearTimeout(timer); }
}
```

🚨 **ต้องใช้ทุกจุดที่คุยกับหลังบ้าน** เหลือ `fetch` ดิบไว้จุดเดียวก็ค้างได้ที่จุดนั้น

ข้อความตอนตัด **ต้องบอกว่ายังไม่รู้ผล และกดใหม่ได้**
`ยังไม่รู้ผลว่าบันทึกเข้าหรือยัง — กดส่งใหม่ได้เลย ระบบกันข้อมูลซ้ำไว้แล้ว`

### ร่างเก็บในเครื่อง

- เก็บหลังหยุดพิมพ์ ~800ms ไม่เก็บทุกตัวอักษร
- 🚨 **ล้างทันทีที่ 1) บันทึกสำเร็จ 2) กดออกโดยไม่บันทึก 3) ออกจากระบบ**
  เพราะร่างมี HN กับข้อมูลผู้ป่วยอยู่ข้างใน
- เปิดฟอร์มมาเจอร่างค้าง → **ถามก่อนว่าจะเอากลับมาไหม** ไม่ใช่ยัดกลับเอง
- 🚨 บันทึกล้มเหลว **ห้ามล้างร่าง** (วาง `clearDraft()` ไว้หลังจุดที่ throw แล้วเท่านั้น)

### ที่ยาคืนมีแต่เว็บอื่นยังไม่มี

**ส่งซ้ำอัตโนมัติเมื่อเน็ตกลับมา** (`retryFailedSave` ใน `MedReturnApp.jsx`)
ผูกกับเหตุการณ์ `online` — เน็ตกลับมาแล้วยิงของค้างต่อเอง

## 31. บันทึกของเซิร์ฟเวอร์ — รู้ว่าเว็บพังเพราะอะไร 🔴

**พี่กันสั่ง 1 ก.ย. 2569** หลังเอเจนต์ตรวจเจอว่าทั้งเว็บ HCV มี `console.error` **ศูนย์จุด**
แล้วถามต่อว่า *"สิ่งนี้ที่เราทำคืออะไร มันเก็บข้อมูลไว้ไหน ควรใช้เป็นสกิลกลางไหม"*

### ปัญหา

ทุก API จับข้อผิดพลาดแล้ว **ทิ้ง stack trace ไปเลย** เหลือแค่ข้อความสั้น ๆ ส่งกลับให้ผู้ใช้

```ts
} catch (e) {
  const msg = e instanceof Error ? e.message : 'บันทึกไม่สำเร็จ';
  return NextResponse.json({ isOk: false, error: msg }, { status: 500 });
}
```

เทียบกับห้องยา — **เหมือนคนไข้แพ้ยาแล้วไม่มีใครจดว่าแพ้ตัวไหน** รู้แค่ว่าแพ้ ครั้งหน้าก็ยังไม่รู้ว่าต้องเลี่ยงอะไร

**เคสจริงที่เสียเวลาทั้งบ่าย** 12 ส.ค. 2569 เว็บพังบนเครื่องคนอื่น เดาสาเหตุผิด 6 รอบติด
(เน็ตช้า · ตัวบล็อกโฆษณา · localStorage · สิทธิ์ Google · นโยบายองค์กร · DNS)
พอได้ดูข้อมูลจริงจบใน 1 นาที

### ต้องมีครบ 5 อย่าง

| # | อย่าง | ทำไมต้องมี |

| 2 | **ปิดบัง HN ก่อนเขียน** | บันทึกเก็บอยู่นอกโรงพยาบาล เลขผู้ป่วยห้ามหลุด |
| 3 | **เปิดสวิตช์ในหน้า Cloudflare** | ไม่เปิดก็ไม่มีที่เก็บ โค้ดเขียนไปก็หายเปล่า |
| 4 | **ใส่ค่าในไฟล์ตั้งค่าให้ตรงกัน** | ไม่ใส่แล้ว deploy รอบหน้าจะทับกลับเป็นปิด |

### อย่างที่ 1 — ตัวช่วยกลาง `lib/apiError.ts`

```ts
import { NextResponse } from 'next/server';
import { maskHn } from './maskHn.ts';

/** ข้อความมีตัวอักษรไทยไหม — ใช้แยกว่าเป็นข้อความที่ตั้งใจเขียนให้คนอ่าน */
const เป็นภาษาไทย = (s: string) => /[฀-๿]/.test(s);

export function apiFail(where: string, e: unknown, fallback: string, status = 500) {
  const raw = e instanceof Error ? e.message : String(e);

  console.error(`[${where}] ${maskHn(raw)}`);
  if (e instanceof Error && e.stack) console.error(maskHn(e.stack));

  // 🚨 ข้อความจากฐานเป็นภาษาช่าง มีชื่อตาราง ชื่อคอลัมน์ ชื่อกฎอยู่ข้างใน
  //    ส่งกลับทั้งดุ้นแล้วผู้ใช้อ่านไม่รู้เรื่อง และคนที่จะเจาะเว็บได้แผนผังฐานฟรี
  //    ข้อความไทยที่ตั้งใจเขียนให้คนอ่าน ส่งต่อได้ เช่น "HN นี้มีอยู่แล้ว"
  //
  // 🚨🔴 ต้องปิดบังฝั่งที่ส่งกลับด้วย ไม่ใช่ปิดบังแค่ตอนเขียนบันทึก
  //    ข้อความที่ฐานสร้างเองมีตัวอักษรไทยปนได้ (ชื่อสถานที่ ชื่อคน ที่อยู่ในกฎของตาราง)
  //    มีไทยแม้ตัวเดียว ทางนี้จะส่งข้อความดิบกลับทั้งดุ้น พร้อมเลขผู้ป่วยที่ติดมา
  //    ไปโผล่บนหน้าจอผู้ใช้ = รูรั่วอีกทางที่การปิดบังฝั่งบันทึกกันไม่ถึง
  const msg = เป็นภาษาไทย(raw) ? maskHn(raw) : fallback;

  return NextResponse.json({ isOk: false, error: msg }, { status });
}
```

### อย่างที่ 2 — ปิดบัง HN `lib/maskHn.ts`

```ts
export function maskHn(s: string): string {
  return s
    // เลขที่ตามหลังคำว่า HN
    // รับทั้ง "HN 14820" · "HN14820" · "hn: 14820" · "(hn)=(14820)"
    // 🚨 ห้ามใส่ \b ปิดท้าย hn — "HN14820" ตัว N ติดกับ 1 ซึ่งเป็นอักขระคำทั้งคู่
    //    จึงไม่มีขอบเขตคำให้จับ แล้วเลขจะหลุด (ชุดทดสอบจับได้ตอนเขียนรอบแรก)
    .replace(/\bhn\s*[:=)(]*\s*[0-9]+/gi, 'HN ***')
    // เลขล้วน 4 หลักขึ้นไปที่ลอยอยู่ในข้อความ (HN ของที่นี่เป็นตัวเลขล้วน 4-6 หลัก)
    // ตัวตรวจหน้าหลังกันไม่ให้ไปโดนเลขบรรทัด ชื่อไฟล์ หรือรหัสสุ่มที่ปนตัวอักษร
    .replace(/(?<![0-9a-zA-Z_.\-:])[0-9]{4,}(?![0-9a-zA-Z_.\-:])/g, '***');
}
```

🚨 **แยกเป็นไฟล์ของตัวเอง ห้ามรวมกับ `apiError.ts`** เพราะตัวนั้น import `next/server`
ซึ่งชุดทดสอบที่รันด้วย `node` ตรง ๆ เรียกไม่ได้

**ทำไมต้องปิดบัง — เจอของจริงมาแล้ว** ข้อความผิดพลาดที่ฐานข้อมูลสร้างเองมี HN ประกอบอยู่ในตัวข้อความ

```
Error: มีผู้ป่วย HN 14820 ที่ใช้งานอยู่แล้ว ต้องแก้ HN ก่อนจึงจะกู้คืนได้
```

ไม่ใช่สิ่งที่เราใส่ลงไป แต่ผลลัพธ์เหมือนกันคือ **เลขผู้ป่วยจริงไปค้างอยู่บนเครื่องของผู้ให้บริการ**

### 🔴 อย่างที่ 5 — ฝั่งเบราว์เซอร์ก็ต้องร้อง ไม่ใช่กลืนเงียบ

**เป็นกฎของทุกเว็บ ไม่ใช่เฉพาะเว็บที่ไม่มีหลังบ้าน** (ยกขึ้นเป็นกฎ 2 ก.ย. 2569)

เดิมเขียนไว้เป็นแค่บันทึกว่า ME-DRP ทำอะไรเพราะไม่มีหลังบ้าน
แต่ **เว็บที่มีหลังบ้านก็มี `catch {}` ในโค้ดฝั่งเบราว์เซอร์เหมือนกัน** และตรงนั้น
**ทำงานบนเครื่องของเภสัชกร ไม่เคยผ่าน worker เลยสักครั้ง** → Workers Logs ไม่เห็นอะไรทั้งนั้น

ตรวจเว็บมูลค่ายาคืน 2 ก.ย. 2569 (ซึ่งมีหลังบ้านครบ) เจอ **6 จุดที่คุยกับเซิร์ฟเวอร์แล้วกลืนเงียบ**

| จุดที่เงียบ | เกิดอะไรถ้าล้ม |
|---|---|
| โหลดร่างจากเซิร์ฟเวอร์ | แถบล็อตค้างไม่ขึ้น โดยไม่มีใครรู้ |
| ถามลายเซ็นคลังยา · โหลดคลังยาใหม่ | แก้ชื่อยาที่เว็บอื่นแล้วที่นี่ยังเห็นของเก่า |
| โหลดการตั้งค่า | รายชื่อ รพ.สต. หายไปเฉย ๆ |
| ยอดสะสมปีงบ (2 จุด) | ตัวเลขค้างของเก่า |

### `lib/clientLog.js` — ฉบับฝั่งเบราว์เซอร์

```js
import { safeErrLine } from './maskHn';

/** ผู้ใช้เสียประโยชน์จริง — ของที่ควรได้ไม่ได้ หรือได้ของเก่าโดยไม่รู้ตัว */
export function logFail(where, e) {
  try { console.error('[' + where + '] ' + safeErrLine(e)); } catch (err) {}
}

/** ล้มได้ตามปกติ แต่ยังอยากเห็นตอนไล่บั๊ก — ที่เก็บเต็ม · โหมดส่วนตัว · ปิดสิทธิ์ */
export function logWarn(where, e) {
  try { console.warn('[' + where + '] ' + safeErrLine(e)); } catch (err) {}
}
```

🚨 **แยก `logFail` กับ `logWarn` ให้ชัด** ใช้ `logFail` กับทุกอย่างจะทำให้คอนโซลเต็มไปด้วยเสียงรบกวน
แล้วเรื่องที่สำคัญจริงจะจมหายไป

🚨 **ปิดบังเลขผู้ป่วยก่อนร้องเสมอ** คอนโซลก็เป็นที่ที่คนอื่นเปิดดูได้
(ยืมเครื่อง · ส่วนขยายที่อ่านคอนโซล · ภาพหน้าจอที่ส่งต่อกัน)

### 🚨 catch ที่กลืนเงียบ "ถูกต้อง" มีจริง — อย่าไปไล่แก้หมด

| กลืนเงียบได้ | ต้องร้อง |
|---|---|
| `localStorage` / `sessionStorage` (โหมดส่วนตัว · พื้นที่เต็ม) | ทุกอย่างที่คุยกับเซิร์ฟเวอร์ |
| `navigator.vibrate` (เครื่องไม่มี) | ทุกอย่างที่ทำให้ผู้ใช้เห็นข้อมูลผิดหรือไม่เห็นเลย |
| `el.setSelectionRange` (ช่องยังไม่พร้อม) | |

**ที่มูลค่ายาคืนเหลือกลืนเงียบ 3 จุดโดยตั้งใจ** — ทั้งสามอยู่ในตารางซ้ายทั้งหมด

### 🚨 กับดัก 3 อย่างที่เจอมาแล้วทุกอัน

**1. HN หลุดลงบันทึกโดยไม่ได้ตั้งใจ**
เจอภายในไม่กี่นาทีหลังใส่ระบบเสร็จ — ข้อความจากฐานมี HN ประกอบอยู่เอง
**ต้องเปิดดูบันทึกจริงหลังใส่ระบบเสมอ** ไม่ใช่เชื่อว่าเขียนถูกแล้วจบ

**2. ไฟล์ตั้งค่ากับหน้าเว็บไม่ตรงกัน**
เปิดในหน้าเว็บอย่างเดียว แล้ว deploy จากเครื่องรอบหน้า → ค่าถูกทับกลับเป็นปิด
บันทึกหยุดเก็บเงียบ ๆ กว่าจะรู้ก็ตอนต้องใช้แล้วไม่มีอะไรให้ดู

---

**3. ปิดบังแค่ตอนเขียนบันทึก แต่ลืมฝั่งที่ส่งกลับ** (เจอ 2 ก.ย. 2569 ที่เว็บมูลค่ายาคืน)
`apiFail` มี **สองทางออก** — เขียนลงบันทึก กับ ส่งข้อความกลับถึงผู้ใช้
ปิดบังทางเดียวแล้วอีกทางยังรั่วอยู่ · ข้อความจากฐานที่มีตัวอักษรไทยปน**แม้ตัวเดียว**
จะถูกส่งกลับทั้งดุ้นพร้อมเลขผู้ป่วย ไปโผล่บนหน้าจอและในบันทึกของเบราว์เซอร์

🚨 **ชุดทดสอบตัวปิดบังจับข้อนี้ไม่ได้** เพราะตัวปิดบังทำงานถูกทุกเคส สิ่งที่พลาดคือ **ลืมเรียก**
ต้องมีชุดทดสอบอีกตัวที่เรียก `apiFail` จริง แล้วดู**ทั้งสองทางออก**
(เว็บมูลค่ายาคืนทำไว้ที่ `scripts/api-fail-proof.mjs`)

ไว้ก่อนถึงฐานเสมอ (ซึ่งถูกแล้ว) จึงเข้า `catch` ไม่ได้เลย ต้องทำให้**ฐาน**พังแทน

1. ทำเซิร์ฟเวอร์เล็ก ๆ ที่ตอบข้อความผิดพลาดแบบที่ฐานส่งจริง แล้ว `listen` พอร์ตว่าง
2. ปิดเซิร์ฟเวอร์ทดสอบ แล้วเปิดใหม่โดยชี้ `SUPABASE_URL` มาที่เซิร์ฟเวอร์ปลอมตัวนั้น
3. ยิงคำขอธรรมดา แล้วเปิดบันทึกดูว่าเขียนอะไรออกมา

ผลจริงที่ได้จากเว็บมูลค่ายาคืน 2 ก.ย. 2569


บันทึกจึงว่างเปล่า — ที่ ME-DRP เปิดสวิตช์ไว้แล้วแต่หน้า Observability ขึ้น **No events found**
(ไม่ใช่สวิตช์เสีย · ไม่ใช่ตั้งค่าผิด · คือไม่มีอะไรให้เก็บจริง ๆ)

| เว็บทำงานยังไง | เปิดบันทึกแล้วเห็นอะไร |
|---|---|
| ผ่านหลังบ้านของตัวเอง (HCV · มูลค่ายาคืน) | เห็นทุกข้อผิดพลาดพร้อมชื่อเส้นทาง — ตามเจตนาข้อนี้ |
| ยิงจากเบราว์เซอร์ตรง (ME-DRP) | เห็นแค่ว่ามีคนเปิดหน้าเว็บ ตอนบันทึกพังไม่เห็นเลย |

🚨 **ก่อนบอกว่าเว็บไหน "ทำข้อ 31 แล้ว" ต้องตรวจก่อนว่าเว็บนั้นมีหลังบ้านไหม**
ไม่มีหลังบ้าน = เปิดสวิตช์ได้ ไฟล์ตั้งค่าถูกต้องได้ แต่**ยังไล่บั๊กจากบันทึกไม่ได้**
ต้องดู Console ของเบราว์เซอร์ (F12) บนเครื่องที่พังแทน จนกว่าจะมีหลังบ้านตามข้อ 24

### 🔴🔴 กับดักที่ 4 — ร้องออกมาแล้วได้ "[object Object]" (2 ก.ย. 2569 ที่ ME-DRP)

เขียนตัวช่วยกลางเสร็จ ทดสอบด้วยฐานที่ต่อไม่ติดจริง แล้วได้บรรทัดนี้

```
[useRecords.loadRecords (ดึงรายงานจากฐานไม่สำเร็จ)] [object Object]
```

**ต้นเหตุ:** `supabase-js` ไม่ได้โยน `Error` แต่โยน**ก้อนข้อมูลธรรมดา** `{ message, code, details, hint }`
โค้ดในสกิลนี้เขียนว่า `e instanceof Error ? e.message : String(e)` — ตกมาทาง `String(e)` ได้ `"[object Object]"`
**ร้องแล้วอ่านไม่รู้เรื่อง = ไร้ประโยชน์พอ ๆ กับเงียบ** แต่หลอกให้คิดว่าทำเสร็จแล้ว

**ต้องดึงเนื้อในออกมาเอง**

```ts
if (typeof e === "object") {
  const o = e as { message?: unknown; code?: unknown; details?: unknown; hint?: unknown };
  // 🚨 ช่อง code ห้ามปิดบัง — รหัสของ Postgres เป็นเลข 5 ตัว (23505 บันทึกซ้ำ · 42P01 ไม่มีตาราง)
  //    ตัวปิดบังจะมองว่าเป็นเลขผู้ป่วยแล้วกลบทิ้ง ทั้งที่เป็นกุญแจดอกแรกของการไล่บั๊ก
  const เนื้อความ = [o.message, o.details, o.hint].filter(Boolean).map((x) => maskHn(String(x)));
  return (o.code ? ["รหัส " + String(o.code), ...เนื้อความ] : เนื้อความ).join(" · ");
}
```

🚨 **เว็บที่ทำข้อนี้ไปแล้วต้องกลับไปตรวจ** — `apiError.js` ของ HCV กับมูลค่ายาคืนใช้ `String(e)` แบบเดียวกัน
ถ้าที่นั่นมีจุดที่ส่งก้อนของ Supabase เข้า `apiFail` ตรง ๆ บันทึกจะเป็น `[object Object]` เหมือนกัน

🚨 **บทเรียนวิธีทำงาน: ต้องทดสอบด้วยของพังจริง ไม่ใช่แค่เขียนเสร็จแล้วเชื่อว่าใช้ได้**
ชุดทดสอบตัวปิดบังผ่านหมดทุกเคสตั้งแต่แรก แต่จับข้อนี้ไม่ได้เลย เพราะตัวปิดบังไม่ได้ผิด
สิ่งที่ผิดอยู่คนละชั้น — ต้องมีชุดที่**เรียกตัวช่วยกลางจริงแล้วดูข้อความที่ออกมา**
(ME-DRP ทำไว้ที่ `scripts/client-log-proof.mjs` · มูลค่ายาคืนที่ `scripts/api-fail-proof.mjs`)
