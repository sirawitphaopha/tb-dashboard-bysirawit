# 🤖 AI Roadmap — อยากให้ AI มาช่วยจุดไหนบ้าง (TB CARE & JOURNEY)

> **สถานะ: แค่ไอเดีย/แพลน ยังไม่เลือกผู้ให้บริการ ยังไม่สร้างโค้ด**
> โครงไฟล์เมื่อเริ่มทำ ดูที่ `CLAUDE.md` → หัวข้อ "AI features (วางแผนไว้)"
> เอกสารนี้ = รวบรวมว่า AI น่าจะช่วยตรงไหนของแอป เรียงตามคุณค่า/ความเสี่ยง เพื่อเลือกทำทีหลัง

## หลักคิด
- **เริ่มจากอ่านอย่างเดียว (read-only) ก่อน** — เสี่ยงต่ำสุด, ไม่แก้ข้อมูลผู้ป่วย
- **AI เป็นผู้ช่วย ไม่ใช่ผู้ตัดสิน** — เภสัชกร/แพทย์ยืนยันเสมอ (โดยเฉพาะเรื่องยา/ขนาดยา)
- **ข้อมูลไหลออกนอกระบบ** → คิดเรื่อง PDPA + ความยินยอม ก่อนเปิดใช้จริง
- ทุกฟีเจอร์เรียกผ่าน `app/api/ai/*` ฝั่ง server (browser ไม่ถือ key, ไม่ส่ง clinical data ดิบ)

## ข้อมูลที่ AI มีให้ใช้ (จาก patient object)
labs[] (LFT/CBC/Renal-UA + threshold ผ่าน `getLabStatus`) · sputum[] (AFB/molecular/ดื้อยา) ·
adr (อาการไม่พึงประสงค์ + โน้ต) · visits[] (SOAP note ข้อความอิสระ) · dot (ปฏิทินกินยา) ·
regimenHistory[] (ประวัติสูตรยา/เหตุหยุด) · comorbidities/concomitantDrugs · outcome

## 🎯 ฟีเจอร์ที่เสนอ (เรียงตามความคุ้ม × ปลอดภัย)

### กลุ่ม A — read-only, เสี่ยงต่ำ, คุ้มสูง (แนะนำเริ่มก่อน)
| # | ฟีเจอร์ | ทำอะไร | ใช้ข้อมูล |
|---|---|---|---|
| A1 | **สรุปเคสผู้ป่วย** | อ่าน labs/sputum/adr/visits/dot/regimen → สรุปย่อ 1 หน้าให้เภสัชกรอ่านเร็ว (คนไข้เป็นใคร รักษาถึงไหน มีอะไรต้องระวัง) | เกือบทั้งหมด |
| A2 | **แปลผล Lab + เตือนค่าผิดปกติ** | ไฮไลต์ค่าที่ผิดปกติ/แนวโน้มแย่ลง (ALT/AST พุ่ง = DILI, Scr ขึ้น = ไตแย่) พร้อมคำอธิบาย | labs[] + getLabStatus |
| A3 | **อ่านแนวโน้มเสมหะ (conversion)** | ดู sputum[] → บอกว่า convert แล้วหรือยัง, M2 ยัง positive ไหม (delayed), มีสัญญาณดื้อยาไหม | sputum[] |

### กลุ่ม B — ช่วยตัดสินใจ, ต้องมี safeguard (ทำต่อจาก A)
| # | ฟีเจอร์ | ทำอะไร | หมายเหตุ |
|---|---|---|---|
| B1 | **ตรวจ drug interaction / ADR** | เช็คยา TB × ยาโรคร่วม (Rifampicin enzyme induction ฯลฯ) + เชื่อมกับ ADR ที่บันทึก | ปัจจุบันมี logic คร่าว ๆ ใน MedsTab — AI เสริมได้ · **ต้องอ้างอิงแหล่ง** |
| B2 | **cross-check ขนาดยา** | ตรวจ dose ที่คำนวณ vs น้ำหนัก/ไตบกพร่อง (eGFR) แล้วเตือนถ้าน่าสงสัย | เสริม `calcDoses`/`calcCrCl` เดิม · เภสัชยืนยันเสมอ |
| B3 | **แจ้งเตือนเชิงรุก (proactive)** | สแกนทุกเคส → ชงรายการที่ต้องตามเป็นพิเศษ (M2 ยัง AFB+, DOT ขาดหลายวัน, Lab critical) | ต่อยอดจาก `generateAlerts` เดิม |

### กลุ่ม C — ช่วยงานเขียน/ค้น (nice to have)
| # | ฟีเจอร์ | ทำอะไร |
|---|---|---|
| C1 | **ช่วยร่าง visit note (SOAP)** | ร่างโน้ตจากข้อมูลโครงสร้าง → เภสัชแก้ต่อ (ไม่บันทึกอัตโนมัติ) |
| C2 | **ถาม-ตอบเกี่ยวกับเคส (chat)** | แชทถาม AI เรื่องเคสนี้ (เช่น "ประวัติดื้อยาเป็นยังไง") — context = ข้อมูลผู้ป่วย |
| C3 | **คลังความรู้ถาม-ตอบ** | หน้า KnowledgeBase (ตอนนี้ "เร็ว ๆ นี้") → ถาม-ตอบแนวทาง NTP/WHO |
| C4 | **สรุป release note / ช่วยแปลไทย-อังกฤษ** | เสริมงานเอกสาร (คุ้มน้อยกว่ากลุ่มคลินิก) |

## ⚠️ ข้อควรระวังก่อนเปิดใช้จริง
1. **PDPA / ความยินยอม** — ข้อมูลคนไข้ออกนอกระบบไปหา provider; ต้องมี DPA/BAA + แจ้งผู้เกี่ยวข้อง
2. **ความถูกต้องทางคลินิก** — AI ต้อง "ผู้ช่วย" ไม่ใช่คนสั่ง; เรื่องยา/ขนาดยา เภสัช/แพทย์ยืนยันเสมอ; ให้ AI อ้างอิงแหล่ง
3. **ต้นทุน** — คิดค่า token ต่อการเรียก; แคช/จำกัดโควตาถ้าจำเป็น
4. **เริ่มเล็ก** — ทำ A1 (สรุปเคส) เป็นตัวนำร่อง วัดผล แล้วค่อยขยาย

## จุดเสียบ (integration points) เมื่อทำจริง
- ปุ่ม/แผงในหน้าเวชระเบียนผู้ป่วย (เมื่อ rebuild → `parts/patient/ai-panel.jsx`) เรียก `/api/ai/summarize`
- แดชบอร์ด: การ์ด "เคสต้องตามพิเศษ" (B3) เรียก `/api/ai/*`
- หน้า KnowledgeBase: กล่องถาม-ตอบ (C3)
