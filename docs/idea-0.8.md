## 1. บริบท

พี่กันเป็น **เภสัชกร รพ.ปรางค์กู่** ทำงาน **TB Clinic** (คลินิกวัณโรค) โดยมี workflow ประจำก่อนถึงวัน clinic ดังนี้:

1. **ก่อนถึงวัน clinic** → ไล่ดูเคส TB ทั้งหมดทีละคน (เตรียมเคส)
2. **คัดกรอง** ว่าเคสไหน "มีประเด็น ต้องให้หมอดู / ต้อง consult"
3. **เขียนโน้ต consult** — เหตุผล + คำถาม + สิ่งที่ขออนุญาตปรับ ถึงหมอ
4. **ปริ้นออกมาเป็นกระดาษทั้งหมด** → ยื่นให้หมออ่านในวัน clinic

### 🔑 จุดสำคัญเรื่อง "ระบบกระดาษ"
- พี่กันเตรียมเคสในระบบดิจิทัล **แต่สุดท้ายต้องปริ้นทุกใบ** เอาไปให้หมออ่าน (ไม่ได้ให้หมอเปิดจอดู)
- เดิมทำใน **Google Sheet** แล้วปริ้น
- แปลว่า output สุดท้ายของแอป = **ใบกระดาษที่ปริ้นสวย ๆ** ต้องยื่นหมอได้จริง

### ปัจจุบันทำใน Google Sheet ยังไง
- **1 แถว = 1 ผู้ป่วย**
- แต่ละแถวมีคอลัมน์: HN, ชื่อ, อายุ, เดือนที่ (mo), CrCl (ประวัติ), BW (ประวัติน้ำหนัก), ธง Ri/Consult, สูตรยา (log ตามเวลา), ช่อง Consult (โน้ตถึงหมอ), ยาอื่น ๆ, Detail (สรุปเคส/ไทม์ไลน์), Start
- **เนื้อหาทั้งหมด พี่กันเขียนเองด้วยมือ** (นี่คือหัวใจที่ต้องเข้าใจ — ดูข้อ 3)

## 2. ปลายทาง

หน้าตาใบ **"TB Clinic"** ที่ปริ้นจริง (อ้างอิงไฟล์ตัวอย่าง `TB_Clinic_01072026.pdf` = ใบจริงวันที่ 1/7/26, 3 หน้า)

เป็น **ตารางแนวนอน (landscape)** คอลัมน์ดังนี้:

| คอลัมน์ | เนื้อหา |
|---------|---------|
| **วันที่มาตรวจ** | นัด visit |
| **HN** | เลขคนไข้ |
| **ชื่อ** | ชื่อ-สกุล |
| **Age** | อายุ |
| **เดือนที่ / Regimen phase** | เช่น `mo 6 > ครบ`, `mo 2`, `4/9 HR`, `2HRZE/7HR` |
| **CrCl** | ประวัติค่าไต + วันที่ (พี่กันคิด Cockcroft-Gault เอง เช่น `CrCl 36 (Cr0.6)`) |
| **BW** | ประวัติน้ำหนัก + วันที่ |
| **Ri / Consult (ธง)** | มาร์กว่าเคสนี้ต้อง consult |
| **Regimen** | log สูตรยาตามเวลา + มาร์ก inc/dec/hold/DILI |
| **Consult** | โน้ตยาว ๆ ถึงหมอ (เหตุผล + คำถาม + สิ่งที่ขออนุญาตปรับ) |
| **ยาอื่น ๆ** | ยานอกเหนือ TB |
| **Detail** | Dx + ไทม์ไลน์เคสเต็ม (อาการ/แลป/CXR/admit ทุก visit) |
| **Start** | วันเริ่มยา |

### 📖 ศัพท์/รหัสในใบ (แคลร์ถอดความไว้ กันลืมตอนทำจริง)

**ยา TB (ตัวย่อ):**
| ย่อ | ยา |
|-----|-----|
| H | Isoniazid (INH) |
| R | Rifampicin (RIF) |
| Z | Pyrazinamide (PZA) |
| E | Ethambutol (EMB) |
| Lfx | Levofloxacin |
| B6 | Pyridoxine (vitamin B6) |
| B / Bco | B-complex |

**สูตรยา (regimen notation):**
- `2HRZE/7HR` = 2 เดือนแรกกิน HRZE (ระยะเข้มข้น intensive phase) + 7 เดือนถัดมากิน HR (ระยะต่อเนื่อง continuation phase)
- มีนับ day / เดือน (`mo 2`, `1/7HR` = สัปดาห์/เดือนที่เท่าไหร่)

**การปรับยา:**
- `inc` = เพิ่มขนาด · `dec` = ลดขนาด · `hold` = หยุดยา
- `re-ch` = re-challenge (ลองให้ยาใหม่หลังจาก hold ไป)
- **DILI** = Drug-Induced Liver Injury (ตับอักเสบจากยา) → เจอแล้วต้อง **hold → re-challenge** เป็นสเต็ป (ในเคสจริงมี DILI รอบ 1, รอบ 2)
- **mkd** = มก./กก./วัน (ขนาดยาต่อน้ำหนักตัว) — พี่กันคิดสดทุกครั้งที่น้ำหนักเปลี่ยน

**ค่าแลปที่ใช้บ่อย:**
- ตับ: AST, ALT, TB (total bilirubin), Alb (albumin), ALP
- ไต: Cr → คำนวณเป็น CrCl
- เบาหวาน: FBS, A1C
- ไขมัน: lipid (LDL / HDL / TG)
- อื่น: Uric (กรดยูริก), CBC (ความสมบูรณ์เม็ดเลือด), INR

**จุลชีววิทยา (ผลเชื้อ):**
- sputum AFB (ย้อมเสมหะ — ตรวจเดือน 2 / 5 / 6)
- PCR / GeneXpert (MTB detected, RIF/INH susceptible หรือ resistance)
- culture (เพาะเชื้อ)

## 3. หน้าที่ของแอป

> 🚨 **พี่กันย้ำชัดเจนมาก:** *"เนื้อหาทั้งหมดเราเขียนเอง แอปไม่ต้องคิดแทน"*

แอปมีหน้าที่แค่ **3 อย่าง** เท่านั้น:

1. **📝 ที่กรอกข้อมูล** — ให้กรอกสะดวก (แทน Google Sheet)
2. **🔔 ระบบเตือน** — ให้ "มองหาง่าย" ← 🎯 **หัวใจจริงอยู่ตรงนี้**
3. **🖨 ปริ้นออกมาเป็นใบ** — เหมือนใบเดิมเป๊ะ ยื่นหมอได้

### 💡 ข้อคิดหลัก (ทำไมต้องมีแอป ทั้งที่มี Sheet อยู่แล้ว)
- **Google Sheet ทำข้อ 1 กับ 3 ได้อยู่แล้ว** (กรอกได้ ปริ้นได้)
- เหตุผล **เดียว** ที่ต้องมีแอป = **ข้อ 2 (ระบบเตือน)** ที่ Sheet ทำไม่ได้
- แอปต้อง **"คอยชี้ธง"** ให้ โดย **ไม่ไปยุ่งกับเนื้อหา** ที่พี่กันเขียน
- คือ พี่กันเขียนงานปกติเหมือนเดิม แล้วแอปแค่คอยสะกิดว่า "เคสนี้มีอะไรต้องดูนะ"

## 4. จุดที่เสียเวลาที่สุด

### 4.1 การ "สรุปเคส" (คอลัมน์ Detail) — เสียเวลาที่สุด 🔴
(อ้างอิงไฟล์ `IMG_4511.png` = ช่อง Detail ใน Sheet ของพี่กัน — ไทม์ไลน์ยาวสีสวย)

- คือไทม์ไลน์ยาว ๆ ที่ไล่ค่า AST/ALT/TB/Alb + DILI รอบ 1/รอบ 2 + admit + CXR + sputum ทีละบรรทัด ตามลำดับเวลา
- พี่กันต้อง **นั่งไล่อ่าน + เรียบเรียง + ไล่ trend ค่าแลปในหัวเองทั้งหมด**
- 🗣️ พี่กันบอกตรง ๆ: **"ทำนานสุด จนช่วงหลังเราไม่ทำเลย"** — เลิกทำเพราะกินเวลา
- แทนที่ด้วย: เขียนตรงในใบ consult แล้ว **ขีดฆ่าออก** เมื่อ consult หัวข้อนั้นเสร็จ
- 🗣️ พี่กันบอก: **"เราก็ไม่รู้จะย่อระบบนี้ยังไง 55555"** ← ข้อ 7 คือคำตอบ

### 4.2 การพิมพ์ค่าแลปด้วยมือ 🟡
- ต้องคีย์ค่าแลปจากโปรแกรม รพ. เข้า Sheet เอง ทีละค่า
- 🗣️ พี่กันอยากให้ **"แคปภาพแลปมา แล้วระบบอ่าน แล้วส่งเข้าช่องค่าแลปเลย"** ← ข้อ 6 คือคำตอบ

## 5. ระบบเตือน + AI (4 ชั้น)

> **ปรัชญาหลัก:** *"AI เป็นผู้ช่วย ไม่ใช่ผู้ตัดสิน — คนที่จบเรื่องยังเป็นพี่กันเสมอ"*
> 🗣️ พี่กัน: *"เราจะผัดมันออกมาเป็นบท consult เอง เพราะมันต้องจบที่เรา"*
> เหมาะกับงานคลินิกที่มีชีวิตคนไข้เป็นเดิมพัน — AI พลาดได้ แต่คนตรวจซ้ำเสมอ

โครงสร้างเป็น **4 ชั้นซ้อนกัน**:

| ชั้น | ใครทำ | หน้าที่ |
|------|-------|---------|
| **1. เตือนอัตโนมัติ** | แอป (กฎตายตัว) | ธงจากข้อมูลตรง ๆ — ถึงเดือน AFB, CrCl ตก, BW เปลี่ยน, มีโน้ต consult |
| **2. AI ส่องจุดบอด** | AI | อ่านทั้งเคส → ชี้จุดที่อาจมองข้าม — drug interaction, lab ที่ลืมตาม, ค่าผิด pattern |
| **3. AI ร่าง consult** | AI | ร่างบท consult ให้ดู **ตามรสมือพี่กัน** |
| **4. พี่กันเกลา + จบ** | พี่กัน | ปรับเป็นคำตัวเอง ตัดสินใจสุดท้าย ← **จบที่เราเสมอ** |

### 🖋 "ตามรสมือเรา" ทำได้จริง (ไม่ใช่ฝัน)
- พี่กันมีตัวอย่าง consult เก่าที่เขียนเองเป็น **ร้อยเคส** (อย่างในไฟล์ตัวอย่างนี่แหละ)
- เราแค่เอาให้ AI ดูเป็น **"ตัวอย่างสไตล์"** (เทคนิค few-shot = ให้ดูตัวอย่างไม่กี่อัน AI ก็เลียนโทนได้)
- AI จะร่างออกมาโทนเดียวกับพี่กัน: ใช้คำว่า *"เภสัชขออนุญาต..."*, *"เรียนแพทย์พิจารณา..."*, วางหัวข้อ 1-2-3-4 แบบพี่กัน
- **ยิ่งพี่กันแก้ มันยิ่งเข้ามือ** (feedback loop)

### 🔗 ชั้น 2-3 ต่อยอดจากชั้น 1
- เตือนแบบกฎตายตัว (ชั้น 1) เห็นแค่ *"ถึงเดือน 2 แล้ว"*
- แต่ AI (ชั้น 2-3) เชื่อมโยงได้: *"ถึงเดือน 2 + AFB ยัง positive + น้ำหนักไม่ขึ้น → น่าจะต้อง extend สูตร ลองพิจารณา consult หมอดู"*
- 🗣️ พี่กัน: *"ทั้งเตือน และ note ในตัว ส่วนเราจะผัดมันออกมาเป็นบท consult เอง"*

### 🚩 ตัวอย่างกฎเตือน (ชั้น 1) ที่เกาะกับคอลัมน์ที่มีอยู่แล้ว
- **เดือนที่** (`mo 6 > ครบ`, `mo 2`) → เตือน *"ถึงกำหนด AFB / ใกล้ครบคอร์ส"*
- **CrCl** → เตือน *"ไตตก ปรับ dose E/Z ตามไต"*
- **BW** → เตือน *"น้ำหนักเปลี่ยน เช็ค dose (mkd)"*
- **ช่อง Consult มีข้อความ** → ธงขึ้นเอง *"เคสนี้มีประเด็น"*
- **LFT (AST/ALT) > 2-3 เท่า** → เตือนเฝ้า DILI

## 6. OCR ค่าแลป

(แก้ pain point 4.2 — การพิมพ์ค่าแลปด้วยมือ)

### Flow การทำงาน
> 📸 พี่กัน **ปริ้นสกรีน** ผลแลปจากโปรแกรม รพ. → 🤖 AI อ่านตัวเลขในรูป → 📋 เด้งค่าเข้าช่องให้อัตโนมัติ (AST, ALT, Cr, FBS...) → ✅ **พี่กันดูแล้วกดยืนยัน** ก่อนบันทึก

- ยังคงหลักการ **จบที่พี่กัน** — AI แค่กรอกร่างให้ พี่กันเป็นคนตรวจว่าอ่านถูกก่อนเซฟ (เหมือนเภสัชคีย์ยาแล้วมี double-check ก่อนจ่าย — เลขแลปพลาดไม่ได้)
- ใช้ท่อ R2 (ระบบอัปรูปที่มีอยู่แล้วในเว็บ) ได้เลย

### ทำไมใช้ได้จริง — เพราะเป็น "ปริ้นสกรีน" ไม่ใช่ถ่ายกล้อง
- 🗣️ พี่กัน: *"แลปจากโปรแกรม รพ แคปจากปริ้นสกรีน... ให้ AI OCR เราไม่ถ่ายกล้องหรอก"*
- ภาพแคปหน้าจอ = **คมชัด ตัวหนังสือเป๊ะ ไม่เบลอ ไม่เอียง ไม่มีเงา** (ต่างจากถ่ายกล้อง)
- → AI อ่านแม่นเกือบ 100% แทบไม่มีพลาด

### 🎁 ของแถม — คำนวณ CrCl อัตโนมัติ
- พอ AI อ่านค่า **Cr** ได้ + แอปรู้ **อายุ / น้ำหนัก / เพศ** ของคนไข้อยู่แล้ว
- → แอป **คำนวณ CrCl ให้เองอัตโนมัติ** (สูตร Cockcroft-Gault)
- พี่กันไม่ต้องกดเครื่องคิดเลขเองทุก visit อีก (เดิมคิดเองทุกครั้ง เช่นในใบ `CrCl 36 (Cr0.6)`)

### แหล่งค่าแลป — 2 ทาง ช่องเดียวกัน
- ตอนนี้: OCR ปริ้นสกรีน
- อนาคต: เชื่อม Himpro (ดูข้อ 9)
- **ทั้งสองทางลงช่องกรอกค่าแลปช่องเดียวกัน** → เปลี่ยนแหล่งได้โดยไม่ต้องรื้อระบบ

## 7. Auto-Timeline

**คำตอบของคำถาม "จะย่อระบบสรุปเคสยังไง"** (แก้ pain point 4.1)

> 🔑 **กุญแจ: พี่กันไม่ต้อง "สรุป" เอง ถ้าแอปเก็บข้อมูลเป็นชิ้น ๆ ตั้งแต่แรก**

### ปัญหาเดิม
- ใน Sheet พี่กัน **พิมพ์รวบ** ทุกอย่างเป็นก้อนข้อความเดียว
  - เช่น `4/2/26: H200 R300 E800 AST 63 ALT 8 TB 1.67 Alb 3.0`
- พอจะสรุปที ต้องมานั่ง **ไล่อ่านก้อนนี้ใหม่หมด** → เสียเวลา

### แนวคิดใหม่
- ในแอป แต่ละ visit พี่กันกรอกเป็น **ช่องแยก** (วันที่ / น้ำหนัก / สูตรยา / AST / ALT / TB...)
- แล้ว **แอปจะต่อไทม์ไลน์ให้เองอัตโนมัติ** — พี่กันไม่ต้องสรุป เพราะมันสรุปตัวเองจากข้อมูลที่กรอกไปเรื่อย ๆ ทุก visit อยู่แล้ว
- 💡 **กรอกครั้งเดียวตอน visit = สรุปไปในตัว** — จ่ายแรงตอนกรอก (ซึ่ง OCR ในข้อ 6 ช่วยให้เร็ว) แล้ว **ไม่ต้องจ่ายแรงซ้ำตอนสรุป**

### สิ่งที่ได้ตามมา (โบนัสจากการเก็บข้อมูลเป็นชิ้น)
- 📈 **กราฟ trend ค่าแลป** — เห็นเลยว่า AST `630 → 581 → 262 → 143 → 75` = กำลังลง (DILI กำลังหาย) โดยไม่ต้องเพ่งอ่านตัวเลขเรียงเอง
- 🤖 **AI ร่างสรุปเป็นภาษาคน** ให้จากข้อมูลนั้น (ตามรสมือพี่กัน) แล้วพี่กันเกลา

### ⚠️ จุดตัดสินใจใหญ่สุด (ยังไม่สรุป — รอตอนทำจริง)
- **ช่องกรอกสูตรยา** จะทำแบบไหน:
  - **พิมพ์อิสระ** — เร็ว คุ้นมือ แต่แอปอ่าน/เตือนไม่ได้
  - **กรอกแยกช่อง** (H: ___ R: ___ Z: ___) — แอปฉลาดขึ้น คำนวณ mkd ได้ เตือนได้ แต่กรอกนานขึ้น
- 🗣️ พี่กัน: *"เรื่องสูตรยาโน้นนี่ เดี๋ยวเราไปสั่งให้เธอทำตอนทำจริงอยู่แล้ว เพราะเราคงแก้ไปมาจนเข้ามือเรา"*
- → **รอพี่กันสั่งตอนทำจริง อย่าเพิ่งตัดสินใจแทน**

## 9. เชื่อม Himpro

**การเชื่อมกับระบบโรงพยาบาลโดยตรง — ความฝันวันหน้า**

### Himpro คืออะไร (ค้นข้อมูลแล้ว 6 ก.ค. 69)
- ระบบสารสนเทศโรงพยาบาล (HIS) ที่คนไทยเขียนเอง ใช้ในหลาย รพ.
- ตัวหลัก **Himpro Offline เขียนด้วย VB6 ตั้งแต่ปี พ.ศ. 2542** (เก่ามาก ~25 ปี)
- **เก็บข้อมูลไว้ใน MySQL** (ฐานข้อมูลมาตรฐานทั่วไป) ← จุดสำคัญ
- มีเวอร์ชัน Himpro On Cloud / Online ด้วย
- **อ้างอิง:** himpro.info
- 🗣️ พี่กัน: *"รพเรา ไม่ใช่ hosXP... มันชื่อ himpro"*

### ✅ ข่าวดี
- Himpro **เก็บใน MySQL (ตู้มาตรฐาน)** — เทียบให้เห็นภาพ: HosXP เหมือนตู้เซฟล็อกแน่นของเจ้าอื่น แงะเข้าไปยากมาก · แต่ MySQL เหมือน **ตู้ยามาตรฐาน** ที่ใครก็เปิดลิ้นชักเป็น
- ถ้าเข้าถึงได้ → **ดึงค่าแลปออกมาตรง ๆ ได้เลย** ไม่ต้องแคป ไม่ต้อง OCR

### ❌ ข่าวร้าย (ด่านที่ต้องผ่าน)
1. **Himpro เก่าเกิน → ไม่มี API / ไม่มี key ให้ขอ**
   - *API เหมือน "ช่องบริการเภสัช"* 💊 = ช่องที่โปรแกรมข้างนอกมายื่นใบขอได้ว่า "ขอค่าแลป HN นี้หน่อย" แล้วระบบยื่นซองคำตอบกลับ · *key API* = บัตรผ่านสำหรับคนที่ได้รับอนุญาต
   - แต่ VB6 ปี 2542 ยังไม่มีแนวคิด "ช่องบริการ" นี้ → **ประตูเดียวที่เข้าได้จริงคือตู้ MySQL ตรง ๆ**
2. **ต้องให้ IT รพ. อนุญาต + ตั้งระบบให้**
   - 🗣️ พี่กัน: *"เราไม่มั่นใจ IT รพ ว่าเก่งคอมเพียงพอนี่สิ 5555"* → ถ้า IT ไม่ถนัด งานนี้จะอืด
3. **เว็บ (เบราว์เซอร์) คุยกับ MySQL ตรง ๆ ไม่ได้**
   - คนละภาษากัน (MySQL ไม่ใช่ภาษาเว็บ/HTTP)
   - ต้องมี **"ตัวแปลภาษา" (โปรแกรมเล็ก ๆ) รันอยู่บนคอมสักเครื่องในวง รพ.** คอยอ่านจาก MySQL แล้วส่งต่อให้เว็บ
   - ตัวแปลตัวนี้แหละที่ต้องให้ IT ช่วยตั้ง
4. **Himpro ใช้ได้เฉพาะต่อ WiFi รพ.**
   - 🗣️ พี่กันเข้าใจถูก: *"ปัจจุบันโปรแกรม himpro ใช้งานได้แค่ต่อ wifi รพ แปลว่าเว็บเราก็ถ้าจะต่อข้อมูลแค่ต่อ wifi รพ ส่วนต่อเน็ตอื่นก็อัปเดตข้อมูลไม่ได้ ก็ไม่เป็นไร"*
   - → การดึงข้อมูลจาก Himpro ต้องอยู่ในวง LAN/WiFi รพ. เท่านั้น

### 📊 สรุป: ทำเป็นขั้น
| ช่วง | วิธีเอาค่าแลปเข้า | ต้องพึ่งใคร | ทำได้เมื่อไหร่ |
|------|------------------|-------------|----------------|
| **ตอนนี้** | 📸 ปริ้นสกรีน → AI OCR | เราคนเดียว | **ทำได้เลย** |
| **อนาคต (ถ้า IT ยอม)** | 🔌 ต่อ MySQL Himpro ดึงตรง (ผ่านตัวแปลในวง รพ.) | ต้องคุย IT รพ. | รอ IT พร้อม |

### 💡 ทำไม OCR ชนะขาดในตอนนี้
| | เชื่อม Himpro ตรง | OCR ปริ้นสกรีน |
|---|---|---|
| ต้องพึ่ง IT รพ. | ✅ ต้อง (ตั้งตัวแปล + ไขกุญแจ DB) | ❌ ไม่ต้องเลย |
| ต้องอยู่ WiFi รพ. | ✅ ตอนดึงต้องอยู่ | ❌ แคปเก็บไว้ อัปจากที่ไหนก็ได้ |
| ทำได้เมื่อไหร่ | รอ IT พร้อม (ไม่รู้เมื่อไหร่) | **ทำได้เลย** |

- ข้อจำกัด "ต่อเน็ตอื่นอัปเดตไม่ได้" ที่พี่กันบอก "ก็ไม่เป็นไร" → สำหรับ OCR **ไม่เป็นปัญหาเลย** เพราะพี่กันแคปหน้าจอไว้ตอนอยู่ รพ. แล้วเอาไปอัปเข้าแอปตอนไหน เน็ตไหนก็ได้
- เชื่อม Himpro เก็บเป็น **ความฝันวันหน้า** — วันไหน IT พร้อม ค่อยเสียบเพิ่ม ไม่เสียหาย เพราะ **ช่องกรอกค่าแลปช่องเดียวกัน** (ดูข้อ 6)

### 🗣️ สเต็ปถ้าอยากลองจริง
- พี่กันลองถาม IT รพ. เบา ๆ ว่า **"ขอสิทธิ์อ่านฐานข้อมูล MySQL แบบ read-only ได้ไหม"** (read-only = อ่านอย่างเดียว แก้ไม่ได้ ปลอดภัยต่อระบบ รพ.)
- ถ้าเขาโอเค → แคลร์จัดการส่วนเทคนิคที่เหลือได้

## 10. ปรัชญาหลัก

**สิ่งที่ต้องยึด ห้ามลืม ตอนทำจริง:**

1. **จบที่พี่กันเสมอ** — AI/แอป ช่วยแค่ ร่าง + ชี้ + เตือน · การตัดสินใจสุดท้าย + เนื้อหาที่ยื่นหมอ = พี่กันเสมอ (คนไข้เป็นเดิมพัน)
2. **ตามรสมือพี่กัน** — ไม่บังคับให้พี่กันเปลี่ยนวิธีเขียน · AI ปรับตามสไตล์พี่กัน ไม่ใช่พี่กันปรับตาม AI
3. **แอปไม่ยุ่งกับเนื้อหา** — พี่กันเขียนงานปกติ แอปแค่คอยชี้ธง
4. **ระบบกระดาษ** — สุดท้ายต้องปริ้นสวย ๆ ยื่นหมอได้จริง
5. **ค่อย ๆ ทำไป** — พี่กันจะสั่งทีละส่วนตอนทำจริง โดยเฉพาะเรื่องช่องกรอกสูตรยา (จะแก้ไปมาจนเข้ามือ) · *"เดี๋ยวไอเดียมันมาเอง"*

## 11. คำถามค้าง

**จุดตัดสินใจ / คำถามที่ต้องเคาะก่อน/ระหว่างทำจริง:**

1. **ช่องกรอกสูตรยา** — พิมพ์อิสระ vs กรอกแยกช่อง (จุดตัดสินใจใหญ่สุด · พี่กันจะสั่งตอนทำจริง)
2. **"ต้อง consult"** — พี่กันมาร์กเองทั้งหมด หรือให้แอปเดาให้ก่อนแล้วพี่กันแค่ยืนยัน
3. **ค่าแลปที่ OCR ต้องดึง** — ยืนยันลิสต์: AST / ALT / TB / Alb / ALP / Cr / FBS / A1C / lipid / Uric / CBC / AFB — ครบไหม ขาดตัวไหน มีตัวไหนไม่ต้องการ
4. **หน้าตาใบปริ้น** — ลอกใบ TB Clinic เดิมเป๊ะ หรือปรับ layout ใหม่
5. **AI provider** — ยังไม่เลือก (ดู `docs/session-notes/2026-07-03-ai-roadmap.md`) · งานนี้ AI ต้องอ่านรูป (vision) ได้ด้วย (สำหรับ OCR แลป) → ต้องเลือกเจ้าที่รองรับ vision
6. **PDPA / ความเป็นส่วนตัว** — พี่กันบอก *"อย่าแคร์ PDPA ขนาดนั้น เพราะข้อมูลเราใช้วงปิด ไม่ได้ออนไลน์ให้ทุกคนอ่าน"* → แต่ตอนเปิดใช้จริง ควรทบทวนอีกที (ข้อมูลคนไข้ส่งออกไปหา AI provider)
