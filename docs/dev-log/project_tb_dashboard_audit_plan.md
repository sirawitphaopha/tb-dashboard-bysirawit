# 📐 แผน: ระบบประวัติการจัดการผู้ใช้ (Audit Log) ครบวงจร

**ที่มา:** 2026-05-22 พี่กันอยากเก็บ "ทุกการกระทำต่อ user" + ใครทำ/แก้/ลบ + ไม่หายตอนลบ user → ขอวางแผนก่อนลงมือ (ตามไม่ทัน)

## 🎯 เป้าหมายสุดท้าย
หน้าประวัติกลางที่ดูได้ว่า **ใครทำอะไร กับ user คนไหน เมื่อไหร่ เพราะอะไร** ครบทุกการกระทำ และ**ไม่หายแม้ user ถูกลบ**

## 📍 สถานะปัจจุบัน (2026-05-22) — สมุดกระจาย 3 เล่ม + ขาด 2 อย่าง
| การกระทำ | สมุดที่เก็บ | snapshot ชื่อ? | หายตอนลบ user? |
|----------|-----------|---------------|----------------|
| อนุมัติ (approve) | ❌ ไม่เก็บ | - | - |
| ปฏิเสธ (reject) | tb_user_reject_log | ✅ มี | ✅ ไม่หาย |
| ปิด/กู้คืน (deactivate/restore) | tb_user_action_log | ❌ ไม่มี | ❌ **หาย (cascade)** |
| แก้ไขข้อมูล (edit) | tb_profile_edit_log | ? ต้องเช็ค | ? |
| ลบถาวร (delete) | ❌ ไม่เก็บเลย | - | - |

(หมายเหตุ: tb_patients_deleted_log = ลบ "ผู้ป่วย" คนละเรื่องกับ user)

## 🛠 แผนทำ — เรียงตามความสำคัญ (ทำทีละขั้น รอพี่กันโอเค)

### ขั้น 1 — 🚨 อุดรูใหญ่: กันประวัติปิด/กู้คืนหายตอนลบ (สำคัญสุด)
- เพิ่ม snapshot ชื่อใน tb_user_action_log (เก็บ ชื่อ/email/username ตอนนั้น เหมือน reject_log)
- เปลี่ยน FK จาก cascade → set null (ลบ user แล้ว log ยังอยู่)
- ⚠️ ต้องรัน SQL
- ผล: ของที่ทำไปวันนี้ (ปิด/กู้คืน) จะไม่หายอีก

### ขั้น 2 — เพิ่มจด "การลบ user"
- ตอนนี้ลบเงียบ ไม่มีร่องรอย → เพิ่มจดลงสมุด (action='delete') ก่อนลบจริง: ใครลบ/เมื่อไหร่/เหตุผล + snapshot ชื่อ
- เพิ่ม popup ใส่เหตุผลตอนลบ (เหมือนปิดบัญชี)
- แก้ app/api/admin/hard-delete-user/route.ts

### ขั้น 3 — เพิ่มจด "การอนุมัติ" (ถ้าต้องการครบจริง)
- approve ก็จดลงสมุด (action='approve')

### ขั้น 4 — หน้าแสดงรวม (รวมทุกสมุดมาดูที่เดียว)
- ปรับแท็บประวัติให้ดึงจากทุกสมุด (reject + action + edit) มารวมแสดงเรียงเวลา
- เห็นครบ: อนุมัติ/ปฏิเสธ/ปิด/กู้คืน/แก้ไข/ลบ ในที่เดียว

### ขั้น 5 — ปรับ UI 2 คอลัมน์ (ที่พี่กันอยากได้)
- จับคู่ ปิด ↔ กู้คืน เป็นแถวๆ (รอบละ 1 แถว) | คอลัมน์ขวาว่าง = "ยังไม่กู้คืน"
- ทำหลังข้อมูลครบ

## 🤔 จุดตัดสินใจสถาปัตยกรรม (ยังไม่สรุป)
- **ทางA: รวมทุกสมุดเป็นเล่มเดียว** (tb_user_audit_log) — สะอาด ดูที่เดียว แต่ migrate 3 ตารางเก่า งานใหญ่ เสี่ยง
- **ทางB: เก็บแยกตามเดิม + อุดรู + หน้ารวมแสดง** — ไม่ทุบของเดิม ทำทีละขั้น เสี่ยงน้อย (แคลร์เอนเอียงทาง B สำหรับ production ที่มีข้อมูลจริงแล้ว)
